## What exists (all in `apps/apple/`)

### Editing (2026-11-21, `rewrite/apple-edit`)

- `Sources/iOS/BoxTextView.swift`: one box. Owns `NSTextContentStorage` + `NSTextLayoutManager` + `NSTextContainer` and draws the layout fragments itself (`draw(_:)`), list markers right-aligned in the indent. Read-only (core's `ContentNode`s) until an editor is attached; then `UITextInput` by EDITOR.md 10.3: `BoxTextPosition`/`BoxTextRange` hold view offsets (UTF-16 of `textForView()`), `UITextInputStringTokenizer`, `UITextInteraction(.editable)` added while focused. `insertText` ("\n" → `key("Enter")`, "\t" → `key("Tab")`), `deleteBackward` → `key("Backspace")`, `setMarkedText`/`unmarkText` → `set_composition`/`finish_composition`, `replace(_:withText:)` → `replace_range` (falls back to select + type if refused), `selectedTextRange` set → `set_selection`, or `select_node` for one object line's U+FFFC; geometry from TextKit 2 (`enumerateTextSegments`, `textSelectionNavigation` hit-testing); `inputDelegate` is told only about changes not made by the protocol call itself. `EngineUndoManager` (the view's `undoManager`) calls the engine. Hardware keys: Cmd chords as `UIKeyCommand`s with `wantsPriorityOverSystemBehavior` (Cmd+B/I/U/E, Cmd+Shift+S/B/7/8, Cmd+Z, Cmd+Shift+Z, Cmd+Y, Cmd+., Cmd+Alt+0–3/C, Cmd+1, Cmd+Return, Cmd+A) → `key()`; `pressesBegan` sends Shift+Enter, Shift+Tab, Delete, Escape and Alt chords (Alt+Shift+Arrows) to `key()` and passes what the engine doesn't take on to UIKit; plain Return/Tab/Backspace arrive through `insertText`/`deleteBackward`; nothing goes to `key()` while composing. Copy/cut/paste through the engine (HTML + plain text on the pasteboard). An open `/` menu shows a small "↵ <first item> · esc closes" hint (no menu UI yet). Position arithmetic out of range answers nil (as UIKit's own views do), not clamped as 10.3 says: the string tokenizer relies on nil.
- `Sources/iOS/BoxText.swift`: `BoxNode` (from `ContentNode`s or the session's `docJson`) and `BoxTextRenderer`, which walks the tree as `nv_editor::ViewText` does, so the drawn string matches the engine's view text offset for offset: hard break as U+2028, mentions/page links/rules/images/files/task lines as U+FFFC image attachments (`allowsTextAttachmentView = false`), a zero-width space after an empty last line (for the caret). If the lengths ever differ it falls back to plain text rather than mis-mapping. Read-only boxes use the same renderer, so a tap lands where it looks.
- `Sources/Shared/PageEditing.swift`: `PageEditHost` (live page or corpus), `BoxEditor` (session + sync: sends `encodeUpdateSince(confirmed)` after each change, folds a failed send into the next, sends everything again on each `Synced`, merges remote changes), `LocalTaskCallbacks`, `CorpusEditHost`.
- `PageCanvasView.swift`: boxes kept per id and updated in place (a remote change no longer rebuilds the page); one tap focuses a box with the caret at the tap (opening its session the first time; sessions stay open while the page is shown, and keep drawing the box), a tap outside the boxes ends editing (`finish_composition`), taps inside the focused box are its text interaction's; pinch/pan/double-tap zoom as before; the content inset follows the software keyboard and the caret is kept in view. `-demoEdit YES` (corpus mode) focuses the first box and types through UITextInput (CI screenshots `edit-*.png`).
- **Threading (finding)**: `EditorSession` calls are synchronous and local (a mutex over the engine and its own yrs doc, no I/O), so they run on the main thread. `LivePage.applyUpdate` / `document()` are local too but take the page's lock, which `close()` holds while joining the socket thread, so they run on `LivePageModel.editQueue`. Network calls stay on `SessionModel`'s serial queue.
- `SessionModel` builds the core with `Core.withStore` (Application Support/Store/notivelo-<host>.sqlite, excluded from backups) and shows the stored workspaces, tree and tasks before the server answers. Untested beyond building.
- Known cosmetic: ordered-list markers wider than the 24 pt indent (`xlviii)`, `AA.`) overlap the start of the text.
- Not done: opening a box while the page isn't connected (nothing happens on tap then), remote cursors and presence (the engine carries cursors; not drawn), ribbon/format UI beyond the keyboard bar's B/I/U, `/`, `[[`, `@` menus, creating/moving/resizing boxes, `UIIndirectScribbleInteraction` (writing outside boxes), task titles editable in the page, Mac editing (still the Markdown preview), sharper text when zoomed in.

- Triggers: pushes to `rewrite/**` touching `apps/apple/**`, `crates/**`, `Cargo.*` or the workflow. Manual dispatch only works once the file is on `main`.
- Steps: Rust 1.99.1 + Apple targets, build NotiveloCore, `xcodegen generate`, iPad/iPhone simulator build, **iPad screenshots** (boots an "iPad Pro" simulator, screenshots sign-in plus 5 corpus pages via `-previewSignedIn YES -page <case>`; artifact `ipad-screenshots`; worth extending to a signed-in flow later, but don't put real credentials in CI), Mac build, then on `[testflight]` in the head commit message: archive with cloud-managed signing (ASC API key), export, check Apple Distribution signature and version 1.99.x, upload with `testFlightInternalTestingOnly`, revoke CI dev certificates before/after (`scripts/ios-revoke-ci-certs.mjs`), list recent builds.
- Versions: `1.99.<run_number>`; build `<mobile.yml's latest run>.<run_number>` (e.g. 130.8), always above uploaded builds and below the next real release build.
- A full run with upload takes about 8–12 minutes; `gh run watch <id> --exit-status` then `gh run view <id> --log | grep -E 'notice\]Uploaded|IOS 1.99'`.
- Risk: the cert-revoke script could revoke a concurrently running `mobile.yml` release's certificate; avoid `[testflight]` while a real release runs.

## How Devon tests this build

- **1.99.27 (130.27)**, editing, on the iPad from TestFlight. Use a test page: edits are real and reach the server. Sign-in and the rest are as in the 1.99.20 steps below.
  1. Open a page. Tap inside a box: the caret appears where you tapped and the keyboard comes up. Type a sentence. Tap another box: editing moves there. Tap empty page: the keyboard goes away.
  2. Have the same page open in the web app. What you type on the iPad should show there within a second or so. Type in the web app (in the box you're editing on the iPad, and in another box): it should appear on the iPad without the caret jumping or the keyboard closing.
  3. Lists: on a new line type `- ` (a bullet list starts), type, Return (next bullet), Return on an empty bullet (leaves the list). The same with `1. `. With a keyboard, Tab / Shift+Tab nest and un-nest.
  4. Backspace at the start of a line joins it to the line above; at the start of a list item it lifts it out of the list.
  5. Autocorrect: type `teh ` (should become "the"); tap a word with a red underline and pick a suggestion; tap a word on the predictive bar.
  6. Dictation: the microphone key, say a sentence; it should be typed at the caret.
  7. If you have a Japanese or Chinese keyboard: type a word, see it underlined while composing, pick a candidate; it should be typed once (and undo in one step).
  8. Apple Pencil Scribble (Settings → Apple Pencil → Scribble): write into the box you're editing; scratch out a word to delete it. Writing on empty page doesn't make a box yet.
  9. With a hardware keyboard: Cmd+B / Cmd+I / Cmd+U, Cmd+Z and Shift+Cmd+Z, Shift+Return (a line break within the paragraph), Tab/Shift+Tab in lists, arrows, Option+Shift+Up/Down (move a line), Cmd+A.
  10. Undo: shake the iPad, three-finger swipe left, the undo arrow above the keyboard, Cmd+Z. Each should undo your own last typing (not someone else's).
  11. Select text (double-tap a word, drag the handles), Copy, then Paste into another box and into the web app (formatting should carry).
  - Not there yet: the ribbon and formatting menus, the `/` menu (typing `/` shows a hint; Enter picks its first item, Esc closes it), `[[` and `@` menus, other people's cursors, adding/moving/resizing boxes, editing a page that hasn't connected, **making tasks on the iPad** (such a task won't exist on the server: don't use `/task` or Cmd+Return yet), editing task titles in the page, images, editing on the Mac. Please note anything that loses or doubles text (especially Return or Shift+Return on a hardware keyboard), puts the caret in the wrong place, or stops syncing.
- **1.99.20 (130.20)**, on the iPad from TestFlight:
  1. The sign-in screen shows "Native preview" and `1.99.20 (130.20) · core 0.1.0 · page format 2`. Sign in with your Notivelo email and password. A wrong password should say "Wrong email or password." under the button.
  2. The sidebar (tap the sidebar button in portrait) shows **Tasks** and your notebooks, open, with their sections folded; open a section (subsections nest) to see its pages in the web app's order. With more than one workspace, a **Workspace** picker sits at the top; switching reloads the tree. Pull down on the sidebar to refresh.
  3. Tap a page: "Opening…", then its boxes at their positions (read-only; pinch to zoom, double-tap). Task lines show title, done and due date from your task list.
  4. With the page open on the iPad, edit that page in the web app (type in a box, add a line, tick a checkbox). The iPad should show each change within a second or so, without jumping back to the top or losing the zoom.
  5. Tap **Tasks**: open tasks by due date, subtasks indented under their parent, "Completed (n)" folded at the bottom. Tap a circle: it ticks at once and moves to Completed; the web app should show it done. Tap it again in Completed to reopen.
  6. Quit the app (swipe it away) and reopen: it should go straight back in (kept sign-in). The person icon at the top of the sidebar → **Sign out** returns to the sign-in screen; reopening the app then asks to sign in again.
  7. Staging: on the sign-in screen, press and hold the version line for 1.5 s: "Server: staging.notiveloapp.com" appears in orange and sign-in now goes to staging. Hold again to go back to production.
  - Not there yet: editing, locked pages ("open in the web app"), images (shown as a placeholder line), comments, search, the task views beyond the one list. Please note anything that fails, especially at steps 1, 4 and 6 (never run against the real server before).
