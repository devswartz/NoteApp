## Requests

- **apple → editor** (open): `can_undo()` / `can_redo()` on `EditorSession` (for `UndoManager.canUndo/canRedo`, which drive the shake-to-undo prompt and the shortcut bar's buttons). apple guesses today: undo is offered after any edit until undo returns false.
- **apple → editor** (open, low priority): a `ViewText` record (text plus the line table) from one call, so the view maps positions without a `pos_to_view_offset` call each (today: a few calls and string walks per change; fine for normal boxes).
- **apple → editor/core** (open): `EditorSession::open_live(LivePage, field, tasks)` on the live page's own doc (the editor stream already asked core for the doc accessor). Today apple moves bytes: after each change `encode_update_since(confirmed)` → `LivePage.applyUpdate`, and on every remote change the whole `LivePage.document()` → `session.apply_update`, per open box.
- **apple → core** (open): the task calls the engine needs: `create_task` with a client-chosen id (the engine makes task ids on the client: `/task`, Mod+Enter), `delete_task`, and setting a task's title. Until then the iPad keeps such changes on the device (`LocalTaskCallbacks`), so a task line made on the iPad points at no task on the server; Devon is told not to make tasks on the iPad yet.
- **apple → core** (open, low priority): `Core.openPage` blocks while it connects, and apple runs every core call on one serial queue, so a slow connect holds up a task tick. Either an async/non-blocking connect, or a note on which `Core` calls are safe to run concurrently (apple would then use a concurrent queue).
- **apple → core** (open): reconnect inside `LivePage` (nv-sync robustness, already planned). Until then apple reopens the page itself after `Failed` / `Closed` (2 s doubling to 30 s; 4401 reopens at once, up to 3 times; 4403 stops).
- **apple → core** (open, low priority): unlocking locked pages in the Core API; apple shows "Locked pages open in the web app for now".
- Done: typed box content (core M4 step 1) is what the page view draws now, for live and corpus pages; x86_64 slices exist (apple still sets `EXCLUDED_ARCHS` for x86_64; harmless, can go).

## What exists (all in `apps/apple/`)

### Editing (2026-11-21, `rewrite/apple-edit`)

- `Sources/iOS/BoxTextView.swift`: one box. Owns `NSTextContentStorage` + `NSTextLayoutManager` + `NSTextContainer` and draws the layout fragments itself (`draw(_:)`), list markers right-aligned in the indent. Read-only (core's `ContentNode`s) until an editor is attached; then `UITextInput` by EDITOR.md 10.3: `BoxTextPosition`/`BoxTextRange` hold view offsets (UTF-16 of `textForView()`), `UITextInputStringTokenizer`, `UITextInteraction(.editable)` added while focused. `insertText` ("\n" → `key("Enter")`, "\t" → `key("Tab")`), `deleteBackward` → `key("Backspace")`, `setMarkedText`/`unmarkText` → `set_composition`/`finish_composition`, `replace(_:withText:)` → `replace_range` (falls back to select + type if refused), `selectedTextRange` set → `set_selection`, or `select_node` for one object line's U+FFFC; geometry from TextKit 2 (`enumerateTextSegments`, `textSelectionNavigation` hit-testing); `inputDelegate` is told only about changes not made by the protocol call itself. `EngineUndoManager` (the view's `undoManager`) calls the engine. Hardware keys: Cmd chords as `UIKeyCommand`s with `wantsPriorityOverSystemBehavior` (Cmd+B/I/U/E, Cmd+Shift+S/B/7/8, Cmd+Z, Cmd+Shift+Z, Cmd+Y, Cmd+., Cmd+Alt+0–3/C, Cmd+1, Cmd+Return, Cmd+A) → `key()`; `pressesBegan` sends Shift+Enter, Shift+Tab, Delete, Escape and Alt chords (Alt+Shift+Arrows) to `key()` and passes what the engine doesn't take on to UIKit; plain Return/Tab/Backspace arrive through `insertText`/`deleteBackward`; nothing goes to `key()` while composing. Copy/cut/paste through the engine (HTML + plain text on the pasteboard). An open `/` menu shows a small "↵ <first item> · esc closes" hint (no menu UI yet). Position arithmetic out of range answers nil (as UIKit's own views do), not clamped as 10.3 says: the string tokenizer relies on nil.
- `Sources/iOS/BoxText.swift`: `BoxNode` (from `ContentNode`s or the session's `docJson`) and `BoxTextRenderer`, which walks the tree as `nv_editor::ViewText` does, so the drawn string matches the engine's view text offset for offset: hard break as U+2028, mentions/page links/rules/images/files/task lines as U+FFFC image attachments (`allowsTextAttachmentView = false`), a zero-width space after an empty last line (for the caret). If the lengths ever differ it falls back to plain text rather than mis-mapping. Read-only boxes use the same renderer, so a tap lands where it looks.
- `Sources/Shared/PageEditing.swift`: `PageEditHost` (live page or corpus), `BoxEditor` (session + sync: sends `encodeUpdateSince(confirmed)` after each change, folds a failed send into the next, sends everything again on each `Synced`, merges remote changes), `LocalTaskCallbacks`, `CorpusEditHost`.
- `PageCanvasView.swift`: boxes kept per id and updated in place (a remote change no longer rebuilds the page); one tap focuses a box with the caret at the tap (opening its session the first time; sessions stay open while the page is shown, and keep drawing the box), a tap outside the boxes ends editing (`finish_composition`), taps inside the focused box are its text interaction's; pinch/pan/double-tap zoom as before; the content inset follows the software keyboard and the caret is kept in view. `-demoEdit YES` (corpus mode) focuses the first box and types through UITextInput (CI screenshots `edit-*.png`).
- **Threading (finding)**: `EditorSession` calls are synchronous and local (a mutex over the engine and its own yrs doc, no I/O), so they run on the main thread. `LivePage.applyUpdate` / `document()` are local too but take the page's lock, which `close()` holds while joining the socket thread, so they run on `LivePageModel.editQueue`. Network calls stay on `SessionModel`'s serial queue.
- `SessionModel` builds the core with `Core.withStore` (Application Support/Store/notivelo-<host>.sqlite, excluded from backups) and shows the stored workspaces, tree and tasks before the server answers. Untested beyond building.
- Known cosmetic: ordered-list markers wider than the 24 pt indent (`xlviii)`, `AA.`) overlap the start of the text.
- Not done: opening a box while the page isn't connected (nothing happens on tap then), remote cursors and presence (the engine carries cursors; not drawn), ribbon/format UI beyond the keyboard bar's B/I/U, `/`, `[[`, `@` menus, creating/moving/resizing boxes, `UIIndirectScribbleInteraction` (writing outside boxes), task titles editable in the page, Mac editing (still the Markdown preview), sharper text when zoomed in.

- `project.yml` (XcodeGen; the `.xcodeproj` is generated, not committed): targets `Notivelo` (iPad + iPhone, iOS 17, bundle ID `com.devswartz.notivelo`, App Group) and `NotiveloMac` (macOS 14, sandbox + network client). Both depend on the local package `NotiveloCore` at `../../target/apple/NotiveloCore` (CI builds it) and bundle `tests/corpus/cases` as `cases`.

Sign-in, `restoreSession` at launch, sign-out; the refresh token lives in the keychain (`Keychain.swift`: generic password, service `com.devswartz.notivelo.native`, account = server URL) and is stored again after every call. - Triggers: pushes to `rewrite/**` touching `apps/apple/**`, `crates/**`, `Cargo.*` or the workflow. Manual dispatch only works once the file is on `main`.

- Versions: `1.99.<run_number>`; build `<mobile.yml's latest run>.<run_number>` (e.g. 130.8), always above uploaded builds and below the next real release build.
- A full run with upload takes about 8–12 minutes; `gh run watch <id> --exit-status` then `gh run view <id> --log | grep -E 'notice\]Uploaded|IOS 1.99'`.
- Risk: the cert-revoke script could revoke a concurrently running `mobile.yml` release's certificate; avoid `[testflight]` while a real release runs.
