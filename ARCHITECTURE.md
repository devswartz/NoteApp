# Architecture

How NoteApp is built today. Read `PLAN.md` for what we're building and `docs/AGENT_GUIDE.md` for how we work. Keep this file accurate: if you change something described here, update it in the same PR.

> Phase 0 foundation is in place. Keep this file current: update it in any PR that changes something described here.

## Stack

| Layer | Choice |
|---|---|
| Web client | React 19, Vite 8, TypeScript, React Router 7, Zustand 5, lucide-react icons, hand-written CSS (`src/styles.css`; design tokens at its top: colour, type, spacing, radius, motion, z-index, safe areas — use the variables, not literal values) |
| Editor | TipTap 3 (ProseMirror) with a custom `taskRef` node, bound to a Yjs doc with `@tiptap/extension-collaboration` |
| Real-time | Yjs over a custom y-websocket-protocol server (`server/collab.ts`); y-indexeddb for the local cache |
| Server | Node 22, Express 5, `ws`, run directly from TypeScript with `tsx` (no compile step) |
| Database | SQLite through `better-sqlite3` (synchronous), WAL mode, FTS5 for page search |
| Auth | Email + password (bcrypt), short-lived JWT access token + rotating refresh token, no cookies (see Auth below) |
| Tests | `node:test` run through `tsx` (`npm test`), against an in-memory SQLite DB |

## Running it

```bash
npm ci
npm run dev        # API on :3001 (tsx watch) + Vite on :5173 (proxies /api, /uploads, /collab to :3001)
# open http://localhost:5173 and create an account

npm run typecheck  # tsc -b over src, server, shared, tests
npm test           # node --test tests/*.test.ts
npm run build      # typecheck + vite build → dist/
npm start          # production (NODE_ENV=production): one Node process serves the API, both WebSockets and dist/ on PORT
```

The **app name** is `APP_NAME` in `shared/config.ts`. It is used by the login screen, server logs, `index.html` (`%APP_NAME%`, replaced by a Vite plugin) and the web app manifest (generated by the same plugin in `vite.config.ts`). Storage keys, IndexedDB names and the DB file keep the `noteapp` prefix on purpose, so a rename doesn't wipe local data.

**Production server** (`server/index.ts` → `server/app.ts`): `/api/*` REST, `/api/events` WebSocket, `/collab/<pageId>` WebSocket, `/uploads/*` files, and the built `dist/` for everything else (hashed `/assets` cached for a year; `index.html` is the SPA fallback). `GET /api/health` → `{"ok":true,"version":"<GIT_SHA>"}` (no auth; 503 if the DB is unusable). On **SIGTERM/SIGINT** it stops accepting connections, saves every open collab document, closes the sockets with code 1012 (clients reconnect), closes the DB and exits, well within the contract's 10 s (a hard exit is forced after 8 s).

### Adding things without conflicts

- **A REST endpoint:** put it in your area's `server/routes/<area>.ts`. A new area gets a new file plus one `api.use(...)` line in `server/routes/index.ts` (a `[shared]` change).
- **A screen:** one line in `src/routes.tsx`.
- **Asking the user something:** `await confirmDialog({ title, message, confirmLabel, danger })` / `await promptDialog({ title, label })` from `src/components/shell/dialogs.tsx`, not `window.confirm/prompt` (those don't work well in the desktop and mobile shells). Shared UI pieces (Button, IconButton, Input, Dialog, Tabs, Badge, EmptyState, Skeleton, Tooltip, menus with `useContextMenu`) are in `src/components/ui.tsx`.
- **A command or keyboard shortcut:** `useCommands(() => [{ id, title, group, keys, icon, run, when }], deps)` from `src/hooks/useShortcuts.ts` inside your component. The ⌘K palette, the `?` overlay and the global key listener all read that one registry (`listCommands()` / `runCommand(id)` are there for the desktop menu). Don't add your own `window` keydown listeners for app-wide shortcuts.
- **Client state for a new area:** create your own small zustand store in your area's folder. Add to `src/store/state.ts` only for genuinely global state.
- **A schema change:** a new file `server/migrations/NNN-name.sql`, with the number the manager reserves for your PR. Never edit a merged migration. If two PRs end up with the same number, the server refuses to start ("Two migrations share number …"), and the second PR to merge renumbers its file.
- **Route tests:** `import { startTestApp } from './helpers/app.ts'`. It starts the real server (API + WebSockets) on a random port with an in-memory DB and has `call(method, path, token, body)` and `signUp(name)`. See `tests/server.test.ts`.

## Data model

```
users
workspaces ──< workspace_members (role: owner | admin | member | viewer) >── users
          ──< workspace_invites (email, role, token_hash, expires_at; emailed link, or applied when that email signs up)
          ──< notebooks (visibility: shared | private; private = its creator + notebook_shares)
                 ──< notebook_shares (user_id: people a private notebook is shared with)
                 ──< sections
                        ──< pages (ydoc BLOB = Yjs state, text = extracted plain text, kind = 'document' | 'canvas')
          ──< tasks (page_id → pages, nullable)
pages_fts (FTS5: page_id, title, text)
tasks_fts (FTS5: task_id, title, description; kept in sync by triggers)
files (uploads: workspace_id, page_id, name, mime, size)
```

- **Hierarchy:** workspace → notebook → section → page. Ordering uses a `position REAL` column per level (insert between two items by averaging).
- **Migrations:** `server/migrations/NNN-name.sql`, applied at startup in numeric order, one transaction each, and recorded in `schema_migrations`. Numbers are **reserved per PR by the manager** and may merge out of order, so gaps are allowed: a lower number that lands after a higher one still runs. Duplicate numbers stop the server. A migration must not depend on a higher-numbered one. Databases created before `schema_migrations` existed are backfilled from `PRAGMA user_version`.
- **Permissions** live in `server/access.ts`. Workspace roles: viewers read, members and up edit, admins manage members, owners manage everything. A private notebook (and its pages and tasks) is visible only to its creator and the people it is shared with (`notebook_shares`, managed by the creator via `PUT /notebooks/:id/shares`), except that a task's assignee and creator can always see it (`TASK_VISIBLE`).
- **Access audit:** `tests/permissions.test.ts` (role × route matrix) and `tests/authz-audit.test.ts` (every `/api` route and both sockets as anon / non-member / viewer / member / private-notebook outsider; it fails CI if a registered route isn't in its table).
- **Invites** (`server/workspaces.ts`, `server/routes/workspaces.ts`): inviting a new email stores a random token (SHA-256 only), valid 14 days, and emails `PUBLIC_URL/invite/<token>` via `server/mail.ts`. `GET /invites/:token` is public (landing page `src/components/sharing/InvitePage.tsx`); `POST /invites/:token/accept` requires the signed-in email to match. Sign-up with an invited email joins automatically (unexpired invites only). Production builds links from `PUBLIC_URL` only.
- **Email** (`server/mail.ts`): `sendMail({to, subject, text, html})` over SMTP (`SMTP_*`, `MAIL_FROM`). Without `SMTP_HOST` it logs recipient and subject (and the body outside production) and returns `{sent: false}`; it never throws.
- **Comments** (`server/routes/comments.ts`, `src/editor/collabComments*.ts`): threads on text selections, anchored by a `comment` mark in the Yjs doc; live `comments` events go only to people who can see the page.
- **Tasks are the single source of truth.** A page never stores task fields. The page document contains `taskRef` nodes holding only a `taskId`; the editor renders each one from the client task store (`src/editor/TaskRef.tsx`). So a task edited on the dashboard updates every note it appears in, and the reverse.
  - Clients create a task with a client-chosen UUID first (`POST /workspaces/:id/tasks` with `id`), then insert the `taskRef` node, so the node never points at a missing row. Retrying with the same id is idempotent.
  - `tasks.page_id` is the task's source note (the plan calls it `source_page_id`; the column is `page_id`). It is set and cleared by the server, not trusted from the document.
  - **Reconcile on save:** when the collab server persists a page (debounced 1 s after the last edit, and when the last client leaves), it walks the Yjs XML tree (`extractDoc`) to get the plain text and the set of `taskRef` ids, then `syncPageTasks(pageId, workspaceId, ids)`:
    - tasks in the set get `page_id = this page` (e.g. moved or pasted from another note);
    - tasks that had `page_id = this page` but are no longer in the doc become standalone (`page_id = NULL`). They are never deleted silently.
    - Each changed task is broadcast as a `task` event.
  - Deleting a page, section or notebook detaches its tasks (they become standalone) rather than deleting them.
  - Recurring tasks: completing one inserts a completed copy (`occurrence_of` = original) for history and rolls the original forward to the next due date (`shared/dates.ts → nextOccurrence`), shifting `reminder_at` by the same offset.

## Auth

`server/auth.ts` (server) and `src/api.ts` (client). No cookies anywhere, so native shells and other origins work exactly like the web app. The API sends `Access-Control-Allow-Origin: *`; that is safe because credentials are bearer tokens, never ambient cookies.

- **Sign-in** (`POST /auth/register` | `/auth/login`) returns an `AuthSession` (`shared/types.ts`): `{ accessToken, expiresIn, refreshToken, user }`.
- **Access token:** a JWT `{sub, typ:'access'}` valid for 15 minutes, sent as `Authorization: Bearer …`. The client keeps it in memory only.
- **Refresh token:** 32 random bytes, valid for 30 days, stored server-side only as a SHA-256 hash (`refresh_tokens`, migrations 002–003). `POST /auth/refresh {refreshToken}` returns a new session and retires the old token (**rotation**). Presenting a retired token again within 60 s (a lost response, a retry, two windows racing) returns the **same** replacement token. The replacement is kept encrypted with a key derived from the retired token, so no second token chain is ever created. Any later reuse is treated as theft and **revokes the whole sign-in** (every token in its `family_id`). `POST /auth/logout {refreshToken}` revokes the family.
- **Client:** the refresh token is persisted by `tokenStore` in `src/api.ts` through `platform.secureStorage` (localStorage on the web, the OS keychain in the shells). Startup calls `/auth/refresh` to restore the session. A timer refreshes a minute before expiry. Any 401 triggers one refresh-and-retry. Refreshes are single-flight per tab and serialized across tabs/windows with `platform.withLock` (Web Locks on the web), each reading the latest stored token, so tabs don't burn each other's tokens.
- **WebSockets:** browsers can't set headers on a WebSocket, so the client offers subprotocols `noteapp.v1, bearer.<accessToken>`. The server reads the token from there (`tokenFromUpgrade`) and answers with `noteapp.v1` only, never echoing the token. `?token=` is accepted in development only. A socket is closed with **4401 when its access token expires** (the client refreshes and reconnects). Collab sockets are also re-checked every 30 s and whenever access changes, and are closed with **4403** if the user lost access to the page. The collab provider gets the current token on every reconnect through a `WebSocket` subclass passed as y-websocket's `WebSocketPolyfill`.
- **Access changes:** any route that can take access away (role or membership change, workspace deleted, notebook made private, page or section moved) calls `accessChanged()` from `server/access.ts`. Live connections subscribe with `onAccessChange()` and re-check themselves, so new routes only need that one call.
- **Password reset and change:** `POST /auth/forgot {email}` always answers `{ok:true}` (no account enumeration) and emails a link to `$PUBLIC_URL/reset?token=…`, at most once a minute per address. The token is a 1-hour JWT `{typ:'reset'}` bound to a fingerprint of the current password hash, so it works once and dies when the password changes; no table is needed. `POST /auth/reset {token, password}` sets the password and revokes every sign-in. `POST /me/password {currentPassword, newPassword}` does the same but returns a fresh session for the current device. UI: "Forgot password?" on the login page, `/reset`, and Settings → Profile (avatar colour and change password, `components/AccountSettings.tsx`). Time zone belongs to the Reminders notification settings.
- **Secrets:** in production the server refuses to start unless `JWT_SECRET` is at least 32 bytes.
- **API base URL:** `VITE_API_URL` at build time, else same origin. `apiUrl()`, `wsUrl()` and `fileUrl()` in `src/api.ts` build every URL; nothing else should hard-code `/api` or `location`.

## Platform adapter (`src/platform/`)

One React codebase runs in the browser, in Tauri (desktop) and in Capacitor (mobile). Everything that differs goes through `platform` (`src/platform/index.ts`, interface in `types.ts`). **App code must not call browser-only APIs directly:** no `localStorage`, `Notification`, `window.open`, `<input type="file">` or `navigator.locks` outside `src/platform/`. Layout APIs (`window.innerWidth`, `matchMedia`, key events) and IndexedDB (y-indexeddb) are fine; they work the same in every WebView.

| `platform.` | Use for | Web implementation (`web.ts`) |
|---|---|---|
| `init()` | one-time setup before render | registers the service worker (production) |
| `kv.get/set/remove` (sync) | small preferences: last workspace/page, sidebar state | localStorage |
| `secureStorage` (async) | the refresh token | localStorage (no keychain in browsers) |
| `notifications.permission/request/show` | reminders | Web Notifications |
| `openExternal(url)` | links leaving the app | `window.open(…, noopener)`; `installExternalLinkHandler()` routes clicks on external `<a>` here |
| `deepLinks.initial/subscribe` | `noteapp://page/<id>`, `noteapp://w/…`, universal links | no-op (the URL is the link); `parseDeepLink()` + `components/DeepLinks.tsx` handle routing |
| `pickFiles({accept, multiple})` | attachments and images | a temporary `<input type=file>` |
| `withLock(name, fn)` | cross-tab/window mutual exclusion | Web Locks API, else just runs |
| `isHidden()`, `focus()` | notification vs in-app toast | `document.hidden`, `window.focus()` |

Shells: `initPlatform()` picks the implementation from `detectPlatform()` through `loadPlatform()`, which dynamic-imports it, so the web bundle never loads shell code. **Desktop (Tauri)** is `src/platform/tauri.ts` (+ `tauri/` helpers: server setup, quick-capture window, dock badge, menu bridge, updater) over the Rust app in `apps/desktop/`; see `docs/DESKTOP.md`. To add Capacitor: implement `Platform` in `capacitor.ts` and add it to the `shells` map in `index.ts`.

**Capacitor (iPhone/Android):** `src/platform/capacitor.ts`, loaded when `window.Capacitor.isNativePlatform()`; the native projects are in `apps/mobile/`. Keychain/Keystore secure storage, local + APNs/FCM push (device token → `POST /notifications/devices` after sign-in), deep/universal links, app badge, haptics, status bar, keyboard and splash handling. It reaches the store and API client through a small bridge loaded after them (no import cycle). Details, build commands and secrets: `docs/MOBILE.md`.

## Offline

- **App shell:** `dist/sw.js` is generated at build time from `src/sw/sw.template.js` by the `serviceWorker` plugin in `vite.config.ts`. It precaches `index.html` and every built asset, under a version derived from the build's file list. Navigations are network-first with the cached shell as fallback, and assets are served cache-first. `/uploads/*` is cached on first view (names are immutable). `/api/*` and `/collab/*` are never cached.
- **Updates:** a new service worker waits rather than taking over a running page. `platform.appUpdates` reports it, and `components/AppUpdates.tsx` shows a sticky "A new version is available — Reload" toast. Reload tells the worker to take over and reloads the page. Registrations check for a new deploy every 30 min and whenever the app becomes visible. The shells will plug their own updater into the same hook.
- **Notes:** each page's Yjs doc is cached in IndexedDB (`y-indexeddb`, `noteapp-page-<id>`), so pages you've opened before load and stay editable offline. Edit rights are remembered per user and page (`noteapp.canEdit.<userId>.<pageId>`). Changes merge when the collab socket reconnects.
- **Everything else, read-only:** `src/store/cache.ts` → `cached(key, path)` caches workspaces, tree, tasks and members in IndexedDB (`src/lib/offlineCache.ts`) under per-user keys (`u:<userId>:…`), and falls back to that copy only when the server can't be reached. Task edits need a connection in v1.
- **Cold start offline:** if the refresh call can't reach the server, `bootstrap()` opens with the cached user and data and shows the offline banner. The events socket keeps retrying with backoff; once it reconnects, the session refreshes and data reloads. `clearLocalUserData()` wipes the data cache, the IndexedDB note copies and cached uploads (`uploads-*` in Cache Storage). It runs on sign-out (even if revoking fails), when startup finds the session rejected (401), and when a different user signs in than the last one on this device.

## Real-time sync

There are two channels:

1. **Collaborative editing — WebSocket `/collab/<pageId>`** (token in the subprotocol, see Auth) (`server/collab.ts`). The client uses `y-websocket`'s `WebsocketProvider` (`src/editor/NoteEditor.tsx`). The server speaks the y-websocket protocol (sync step 1/2 + updates, and awareness for cursors and presence). There is one in-memory room (`Y.Doc` + awareness) per open page. Permission is checked when the socket connects; viewers may send sync step 1 but their updates are dropped. Rooms persist to `pages.ydoc` (debounced), update FTS, reconcile tasks and emit a `tree` event. `closeRoom(pageId)` kicks everyone (code 4403) when a page is deleted or its access changes; the client stops reconnecting on 4401/4403. On SIGINT/SIGTERM `flushAll()` saves pending rooms. Each page is also cached locally with `y-indexeddb` (`noteapp-page-<id>`), so it opens offline and merges when the socket reconnects.

2. **Live events — WebSocket `/api/events`** (token in the subprotocol, see Auth) (`server/events.ts`). Server → client only. Each message is one JSON `ServerEvent` (`shared/types.ts`): `task`, `task-deleted`, `tree`, `members`, `workspaces`. Events are filtered per user: a task event goes only to members who can see the task; members who can't get `task-deleted` instead. The server pings every 25 s and drops dead sockets. The client (`src/store/events.ts`) upserts tasks (ignoring stale echoes by `updatedAt`), and refetches the tree/members (debounced) on `tree`/`members`. It reconnects with jittered exponential backoff (1 s → 30 s; immediately when the browser comes back online), stops on close code 4401 (bad token), and after a reconnect refetches the tree and tasks to cover anything missed. Until PR 3 this channel was server-sent events; it was switched to a WebSocket to match `docs/DEPLOY_CONTRACT.md` and so that token auth works the same way for both sockets. **Catch-up:** every published event gets a sequence number in an in-memory buffer (last 2000). The client reconnects with `?since=<boot>:<seq>`; the server replays what it missed, filtered by the user's current permissions (private-page comments withheld, notifications only to their recipient), or sends one `resync` if the gap isn't buffered or the server restarted, then `hello {boot, seq}` as the new cursor.

Client-side task writes are optimistic with rollback (`createTask`, `updateTask`, `deleteTask` in `src/store.ts`); the server response and the event echo then replace the optimistic copy.

## API surface (today)

All under `/api`, JSON, bearer token except where noted:

- `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh` → `AuthSession`; `POST /auth/logout` (no access token needed)
- `GET /health` (no auth)
- `GET/PATCH /me`; live events are the `/api/events` WebSocket, not REST
- `GET/POST /workspaces`, `PATCH/DELETE /workspaces/:id`, members: `GET/POST /workspaces/:id/members`, `GET /workspaces/:id/team?today=` (members + open/overdue/due-today counts), invites `POST /workspaces/:id/invites/:email/resend`, `GET /invites/:token` (no auth), `POST /invites/:token/accept`, notebook sharing `GET/PUT /notebooks/:id/shares`, comments `GET/POST /pages/:id/comments`, `POST /comment-threads/:id/replies`, `PATCH/DELETE /comment-threads/:id`, `PATCH/DELETE /comments/:id`, `PATCH/DELETE /workspaces/:id/members/:userId`, `DELETE /workspaces/:id/invites/:email`
- Tree: `GET /workspaces/:id/tree`, `POST /workspaces/:id/notebooks`, `PATCH/DELETE /notebooks/:id`, `POST /notebooks/:id/sections`, `PATCH/DELETE /sections/:id`, `POST /sections/:id/pages`, `GET/PATCH/DELETE /pages/:id`
- Tasks: `GET /workspaces/:id/tasks` (open + completed in the last 30 days), `GET /workspaces/:id/tasks/completed?before=`, `POST /workspaces/:id/tasks`, `PATCH/DELETE /tasks/:id`
- Moves/copies: `POST /pages/:id/move {sectionId?, index?}`, `POST /pages/:id/copy {sectionId?, title?}` → `{id}` (embedded tasks are duplicated, so the copy never steals the original's tasks), `POST /sections/:id/move {notebookId?, index?}`, `POST /sections/:id/copy {notebookId?, name?}`, `POST /notebooks/:id/move {index}`. `index` is the 0-based slot among the destination's siblings (omit for the end).
- `GET /workspaces/:id/search?q=&limit=` → `SearchResult`: FTS5 over page title + text (`pages_fts`) and task title + description (`tasks_fts`, trigger-maintained, migration 003). Terms are prefix-matched and stemmed, all must match, title hits rank 10× body hits; snippets mark hits with `«…»`.
- Files: `POST /workspaces/:id/files?pageId=` (raw body as `application/octet-stream`, `X-Filename` URI-encoded) → `UploadedFile`; `GET /files/:id` (metadata, workspace members only); legacy `POST /uploads`. Bytes at `$DATA_DIR/files/<id><ext>`, metadata in `files`, served by `serveUploads` at `/uploads/<id><ext>` without auth (128-bit random ids). Only allow-listed extensions are kept (`SAFE_TYPES` in `routes/files.ts`); the served type comes from that list, never from the client. Every file gets `nosniff` and `CSP: sandbox`; everything but raster images is `Content-Disposition: attachment`.

Known rough edges and accepted v1 tradeoffs:
- **`/uploads/*` is served without auth.** Files get unguessable 128-bit random names and are only linked from notes. Anyone holding a file's URL can fetch it, even after losing access to the note. This keeps images working in `<img>` tags, which can't send bearer tokens. Revisit with signed, expiring URLs if that matters.
- The main JS bundle is about 1 MB (no code splitting yet).
